# 实测，不要假设

文档与注释陈述的是"今天的行为"，而一条操作断言唯一可采信的证据是"跑过"。

## 规则

1. **声称前先执行**。写进文档的每条命令、配置片段、默认值、错误路径，按文档将要展示的样子在当前 checkout 上跑一遍；只写观察到的结果，包括确切输出与失败形态。
2. **服务端行为断言必须有证据家背书**（见下节）。对 SAP 行为的新断言，先在证据家记录实测证据，再写进代码注释或文档。
3. **依赖无法满足时点名验证者**。缺真实系统、缺凭据、缺网络时，不断言行为；写明"未能验证"并指出应由谁在何种环境验证。测试被 skip 不等于断言被验证。
4. **复现不了就删**。禁止从记忆、类比、相邻仓库的 README 搬运命令、字段、默认值。断言与观察冲突时修断言，不是修事实。
5. **Eclipse 抓包只是假设**。观察到的请求形态在实测确认前只能作为待验证假设（前车之鉴：`stateful;enqueue` 头误用与"JCo 限制"误判）。

## 本仓库的证据家

- **`npm run verify:stdio` / `npm test` / `npm run check`** —— 服务器自身协议与工具行为的证据。
- **SAP 系统行为** —— 归属 [abap-adt-api](https://github.com/lingcSun/abap-adt-api) 的证据面（真实系统集成测试）；本仓库不产生对 SAP 行为的新断言，引用库行为时以该库的验证为准。`npm run verify:live` 需要真实连接，无法运行时按规则 3 处理。

## 校验

发布前跑 `npm run build` 与 `npm test`；重读 diff 中每条操作断言，逐条对应到执行证据或证据账本条目，对应不上的删掉。
